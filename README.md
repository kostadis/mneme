# hypostasis + mneme

Two commands (same repo) that turn the campaign/DGX system from "works through operational
discipline" into a configured, honestly-reported, reproducible system.

```
  hypostasis            ← configure the ENVIRONMENT (run once)
      │                    install shared libs · render shared config · honest status
      ▼ instantiated per campaign by
  mneme up <campaign>   ← run CampaignGenerator on that environment (run each time)
```

- **`hypostasis`** configures the environment from one hand-edited authority, `hypostasis.yaml`.
- **`mneme`** is spun up for a specific campaign — it runs on the environment hypostasis prepared.

The doctrine behind it lives in `.specify/memory/constitution.md`; the design in
`specs/001-reproducible-install/`; open questions in [GitHub Issues](https://github.com/kostadis/mneme/issues).

## Install

```bash
pip install .                          # provides two commands: `hypostasis` and `mneme`
mkdir -p ~/.config/hypostasis
cp hypostasis.example.yaml ~/.config/hypostasis/hypostasis.yaml   # then edit it
```

Your real environment config lives at **`~/.config/hypostasis/hypostasis.yaml`** (XDG —
override with `$XDG_CONFIG_HOME` or `--config`), **never in the repo**. The committed
`hypostasis.example.yaml` is the placeholder template.

## `hypostasis` — configure the environment (run once)

| Command | What it does |
|---|---|
| `hypostasis install` | install each component at its exact pin (non-editable) in dependency order — or, under a declared `mode: dev`, local `path` components editable (`-e`), pin optional — then render each component's native config from `hypostasis.yaml` |
| `hypostasis apply` | re-render derived configs so nothing runs on a stale copy (Principle V) |
| `hypostasis status` | report **observed** state — component drift (source HEAD vs pin; in `mode: dev`, `editable @ <sha>` (+dirty) plus a check that the venv install is truly editable), service reachability, render drift — never declared. Exit 0 only if every row PASS (Principle I) |

`hypostasis.yaml` is the single authority: `venv`, `machines`, `data_roots`, `env`, `services`,
`components`, and `order`. Rendered component configs are derived (stamped, do-not-edit,
regenerated by `apply`) — never a second source of truth.

## `mneme` — spin up a campaign (run each time)

```bash
mneme integrate out-of-the-abyss          # claim ownership only (no provisioning) — `up` does this automatically too
mneme up out-of-the-abyss --port 5000     # gate substrate · render wiring · export env · start CG
mneme up out-of-the-abyss --dry-run       # preview the plan, start nothing
mneme down out-of-the-abyss --port 5000   # stop that instance
```

`mneme up <campaign>` resolves the campaign workspace (`data_roots.campaigns/<campaign>`),
**health-gates** the shared substrate (won't start on a dead DGX/rpg-lib — Principle I) **and the
campaign's mempalace store** (fails if it isn't brought up — run `mneme mp bringup` first; 003 never
brings the store up from `up`), refreshes CG's wiring, **exports `hypostasis.yaml`'s `env:`** into
CG's process, and starts CampaignGenerator scoped to that campaign on its own port. `mneme integrate
<campaign>` writes `.mneme/owner.yaml` only (no provisioning); since `up` already auto-integrates an
un-integrated campaign, standalone `integrate` is for explicitly claiming ownership ahead of time.

## `mneme mp` — manage the per-campaign mempalaces (feature 002)

Each campaign keeps a semantic index ("mempalace") over its adventure docs. `mneme mp`
manages them all from a **single authority per campaign** that lives *in the campaign*
(`.mneme/mempalace.yaml`) — wings, room/keyword routing, exclusions, and the recorded
**dispositions** (why a campaign diverges). The per-wing `mempalace.yaml` + `.mempalaceignore`
are **stamped, do-not-edit renders** of that authority. mneme owns only the shared **recipe**
(`mneme/recipes/`); writes go through a private working copy, never your active checkout.

```bash
mneme mp bringup CAMPAIGN         # NEW campaign → configure + provision + first-mine + back up (003)
mneme mp backup CAMPAIGN          # snapshot the bindings (store.sqlite3); restore preserves them
mneme mp restore CAMPAIGN         # bring bindings back WITHOUT re-embedding (turbovecdb auto-prunes)
mneme mp regenerate CAMPAIGN --confirm   # the ONLY re-embed-from-scratch path (e.g. model change)
mneme mp status [CAMPAIGN]        # per-campaign state incl. store/backup/faces dims (+ why)
mneme mp refresh --all            # (re)mine every campaign from its own wings, correct order
mneme mp prune CAMPAIGN           # PREVIEW removing drawers whose source is missing/gitignored (refresh never prunes)
mneme mp prune CAMPAIGN --confirm --expect N  # N = count the preview showed; backs up, deletes only that set, re-verifies (--no-backup to skip)
mneme mp render CAMPAIGN --check  # is the derived config still coherent with the authority?
mneme mp faces CAMPAIGN           # re-render the four faces (cli/cg_search/global_alias/mcp) from the authority
mneme mp publish --recipe 2.0.0   # stage a recipe upgrade for all campaigns on a proposal branch
mneme mp adopt CAMPAIGN           # campaign-side gate: stage the upgrade on a branch...
mneme mp adopt CAMPAIGN --here --confirm   # ...or write it into your checkout (uncommitted, FR-030)
mneme mp migrate CAMPAIGN --plan plan.json   # run a human-approved, verbatim migration; then verify
mneme mp bootstrap CAMPAIGN       # write a starter authority into a campaign that has none
mneme mp drop-legacy CAMPAIGN --confirm   # remove dead chroma legacy (sqlite + segments + marker) from the store
mneme mp mcp                      # MCP server: status/target/inventory/instructions + confirm-gated adopt
```

| Concept | Where it lives | Editable? |
|---|---|---|
| per-campaign authority (`.mneme/mempalace.yaml`) | in the campaign | ✅ the one place |
| derived wing `mempalace.yaml` + `.mempalaceignore` | in the campaign | ❌ rendered, stamped |
| recipe (mechanical + scaffold) | `mneme/recipes/` (mneme-owned) | versioned |
| dispositions (the recorded "why") | in the campaign authority | ✅ human-authored |
| mempalace index | `~/.mempalace` (mempalace's store) | — (mneme keeps no copy) |

The mneme-owned **recipe** is the enforceable counterpart of the campaigns repo's prose
`MEMPALACE_HOWTO.md`; the same method is served on demand by `mneme mp mcp` (so an assistant
loads it instead of you pasting docs). Design: `specs/002-manage-campaign-mempalaces/`.

### Declared corpus (feature 007)

A campaign can declare exactly which files are its corpus in `.mneme/corpus.yaml`, which
replaces the wing model for that campaign. Nothing is mined that the file does not name.

| In `corpus.yaml` | Meaning |
|---|---|
| `kinds:` (standard kinds) | each maps to `dirs:` (recursive) and/or `files:` (exact), campaign-relative |
| `campaign_kinds:` | campaign-defined kinds; `trust:` is required (no default) |
| `trust:` | optional override of the kind's default (`authoritative` / `reference`) |
| `mined_as: true` | a file reachable from two kinds is mined as this declaration's kind |

```bash
mneme corpus init CAMPAIGN        # write a skeleton corpus.yaml (never overwrites)
mneme corpus check CAMPAIGN       # validate the declaration against the disk
mneme corpus toc CAMPAIGN [--kind K] [--json]   # resolve NOW and print (the consumer entry point)
mneme corpus current CAMPAIGN     # what the palace actually holds, by file
mneme corpus consumers [--noncompliant]   # known consumers of campaign files and their compliance
```

For a corpus campaign the `mp` commands behave differently:

- `mp render` / `mp faces` derive the wings from the kinds, write the root `mempalace.yaml` and
  the TOC snapshot, and remove wing-model renders.
- `mp refresh` mines per kind from the resolved file list; nothing outside the corpus is mined.
- `mp status` adds a `corpus` row (the palace equals the declaration) and takes the `index` row
  from that same comparison. A fleet-level `consumers` row counts non-compliant consumers; like
  an undeclared corpus it is owed work, exit 0, never a failure (an invalid `consumers.yaml` is).
- `mp prune` deletes undeclared and missing drawers (preview, then `--confirm --expect N`, backed
  up, re-verified). Drawers of a former authoritative wing need `--include-former-canon WING`.
- `mp regenerate --confirm` rebuilds the palace from the declared corpus.

Consumers must ask `mneme corpus toc` (or the `corpus_files` MCP tool), which resolve the
declaration fresh. They must never read `.mneme/corpus.toc.json`: it is a derived, git-ignored
snapshot that status checks for staleness, not an interface.

## What hypostasis manages (the component model)

| Component | Kind | hypostasis installs? | renders config? |
|---|---|---|---|
| CampaignGenerator | mneme-native service | ✅ | ✅ (the only one) |
| mempalace | mneme-native DB (env-driven) | ✅ | — (`env:`) |
| turbovecdb | private storage (embedded) | ✅ | — |
| dgxlib | sovereign driver (→ physical DGX) | ✅ | — |
| dgx | external resource | — (health-checked) | — |
| rpg-lib | external index service | — (health-checked) | — |
| claudelib | external (rpg-lib's dep) | — | — |
| gm-assistant | markdown workspace content | — | — |

The DGX and rpg-lib are **substrate** — hypostasis references and health-checks them but does not
start them (see [#1](https://github.com/kostadis/mneme/issues/1)).

## Reproducibility acid test (SC-005)

```bash
bash specs/001-reproducible-install/validation/run-validation.sh         # on the host
docker compose -f specs/001-reproducible-install/validation/docker-compose.yml run --rm validate
```

In a clean environment it proves: both commands install, `status` runs honestly, `apply` renders
with no stale copy (SC-004), and `mneme up --dry-run` previews the launch incl. env-delivery.

The **003 bring-up acid test** is a separate proof environment (real mempalace + turbovecdb, two
embedder lanes — with and without the Qwen substrate), against a throwaway `$HOME/.mempalace`:

```bash
docker compose -f specs/003-new-campaign-mempalace/validation/docker-compose.yml run --rm validate-onnx
MEMPALACE_EMBEDDING_ENDPOINT=http://<embed-host>:<port> \
  docker compose -f specs/003-new-campaign-mempalace/validation/docker-compose.yml run --rm validate-qwen
```
